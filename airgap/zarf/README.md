# Air-gap packaging (mode B2)

The enclave receives software only as signed Zarf packages carried in on approved media.

## How the enclave gets its software

| What | Carried as | Used in the enclave by |
| --- | --- | --- |
| This repository and two other git sources | Zarf `repos` | Argo CD, from the enclave git server |
| Argo CD | Zarf `charts` | Installed by Zarf, before anything else |
| Every other Helm chart | OCI artefacts in Zarf `images` | Argo CD, as `oci://.../charts/<chart>` sources |
| Container images | Zarf `images` | The cluster, from the enclave registry |
| LangSmith chart and images | A separate package (`airgap/zarf-langsmith`) | As above; needs an offline licence |

The Argo CD applications in `platform/apps` name upstream Helm repositories. The B2 overlay replaces each with an
OCI source on a placeholder host; the Zarf agent rewrites that host to the enclave registry, and git addresses to
the enclave git server, when the applications are created. This is Zarf's documented Argo CD pattern.

Everything here except `images-extra.txt` and `images-langsmith-extra.txt` is generated by `scripts/gen_airgap.py`
(`make airgap`). CI fails if the generated files do not match `platform/apps` and the rendered charts.

## Steps

1. Connected side: `make zarf-package CHART_REGISTRY=<registry[/project]>`. This copies the pinned charts into
   that registry (`airgap/push-charts.sh`) and builds both packages, each with an SBOM.
2. Sign each package with the platform cosign key (`zarf package sign`) and record the hashes in the evidence
   bucket.
3. Carry the packages, the cosign public key and the Sigstore trust root into the enclave.
4. In the enclave: `zarf init` (registry and git server), then `zarf package deploy` for each package.
5. `kubectl apply -f platform/argocd/project-b2.yaml -f platform/argocd/root-b2.yaml`. Argo CD syncs the platform
   from the enclave git server and registry.

## Not yet proven

None of this has run against a Zarf registry or an enclave (issue 16). In particular: that Argo CD accepts a git
`$values` reference alongside an OCI chart source; that `images-extra.txt` is complete; and that the placeholder
host is rewritten for every application. Model weights are carried separately, after `model-intake` approval.
